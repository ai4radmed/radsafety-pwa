# 테스트 명세: 프로덕션 브라우저 스모크 (E2E)

## 대상 구현체

- 경로: 프로덕션 배포 전체 (https://radsafety.kr) — 특정 소스 파일이 아닌 "브라우저에서 실제로 그려지는가"를 검증
- 관련: `.github/workflows/health.yml` (매일 아침 헬스체크에서 실행)

## 배경 (왜 존재하는가)

`scripts/check-production.mjs` 는 순수 HTTP 점검이라 **HTML 이 200 으로 온 이후 브라우저 안에서 벌어지는 일**(JS 크래시로 인한 백지 화면 등)을 보지 못한다. 이 사각지대를 메우는 최소한의 브라우저 점검. **로그인·발송 등 부작용은 절대 수행하지 않는다** — 공개 화면 열람만.

## 테스트 도구

Playwright (E2E) — chromium

## 실행 조건 (게이트)

- **`SMOKE_BASE_URL` 환경변수가 설정된 경우에만 실행.** 미설정이면 전체 skip.
- `SMOKE_BASE_URL` 설정 시 playwright 는 `production-smoke` 단일 프로젝트로 동작: **dev 웹서버를 띄우지 않고** baseURL 을 해당 값으로 잡는다.
- 평상시 CI e2e(`test.yml`)·로컬 `npm run test:e2e` 에서는 chromium 프로젝트의 `testIgnore` 로 제외 — 프로덕션을 향하지 않는다.
- 실행 예: `SMOKE_BASE_URL=https://radsafety.kr npx playwright test`

## 검증 항목

| describe        | it                                    | 검증 내용                                                                                     |
| --------------- | ------------------------------------- | --------------------------------------------------------------------------------------------- |
| 프로덕션 스모크 | 홈이 JS 크래시 없이 렌더링된다        | `/` 로드 후 타이틀(RadSafety\|방사선)·주요 네비게이션 링크 표시, `pageerror`(미처리 예외) 0건 |
| 프로덕션 스모크 | 로그인 화면이 JS 크래시 없이 그려진다 | `/login` 로드 후 이메일 OTP 폼(`#emailOtpRequestForm`) 표시, `pageerror` 0건                  |

## 핵심 규칙

1. **부작용 0** — 폼 입력·제출·로그인 시도 금지. 페이지 열람과 DOM 확인만.
2. `pageerror`(브라우저 미처리 예외)만 실패 사유로 삼는다. `console.error` 는 서드파티 소음으로 플레이크를 만들 수 있어 **로그로만 남기고 실패시키지 않는다** (매일 아침 오탐 경보 방지).
3. 프로덕션은 응답 편차가 있으므로 판정 대기는 여유 있게(15s) 잡는다.
