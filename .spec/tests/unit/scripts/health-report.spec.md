# 테스트 명세 — `scripts/health-report.mjs`

대상 구현체: `scripts/health-report.mjs`
테스트 구현체: `tests/unit/scripts/health-report.test.ts`

## 역할

`check-production.mjs --summary=<path>` 가 남긴 요약 JSON 을 읽어 **텔레그램 보고 문안**을 만들고 발송한다.
발송(네트워크)은 부작용이므로 **문안 생성(`formatReport`)만 순수 함수로 분리**하고, 단위 테스트는 이 함수만 검증한다.

## 보고 모드 (`HEALTH_REPORT` 저장소 변수)

| 값             | 동작                                        |
| -------------- | ------------------------------------------- |
| 미설정 · `all` | 정상·이상 모두 매일 발송 (기본, 하트비트)   |
| `fail`         | 이상일 때만 발송 (정상은 침묵)              |
| `off`          | 발송하지 않음 (헬스체크·GitHub 알림은 유지) |

## 항목 표기 방식 (`HEALTH_REPORT_STYLE` 저장소 변수 · 수동 실행 입력)

점검 항목 라벨은 `check-production.mjs` 가 **콘솔(개발자)용**으로 붙인 기술 용어다(`[4] schema`·`HSTS 헤더 존재`).
콘솔은 그게 맞으므로 **점검 스크립트는 건드리지 않고, 보고 계층에서만 쉬운 말로 옮긴다.**

| 값               | 항목 줄                                                   |
| ---------------- | --------------------------------------------------------- |
| 미설정 · `plain` | 쉬운 말 한 줄 (기본) — `1-2. 암호화 접속(https) 강제 [o]` |
| `both`           | 기술 원문 + 들여쓴 쉬운 말 2줄                            |
| `tech`           | 기술 원문 한 줄 (2026-08-03 이전 표기)                    |

- 사전(`PLAIN_EXACT`·`PLAIN_DOCTOR`·`PLAIN_RULES`)에 없는 라벨은 **어느 방식에서든 원문 그대로** 나온다.
  번역이 없다고 항목이 사라지면 총합 `(N/N)` 이 어긋난다 — 점검 항목이 새로 생기면 사전에 한 줄 추가.
- 쉬운 말은 **명사형**으로 쓴다("데이터베이스 응답", "홈 화면 열림"). 판정은 줄 끝 표식이 지므로,
  서술문("…응답합니다")으로 쓰면 실패 시 `…응답합니다 [x]` 처럼 문장과 표식이 서로 반대말이 된다.

## 문안 형식 (2026-08-03 개정 — 번호식·무이모지)

받는 사람은 **아침에 폰으로 한 번 훑는다.** 그래서 문안은 이모지 없는 차분한 평문이고,
세부항목은 **한 줄씩 번호**로, 상태 표식은 **줄 맨 끝**에 온다(눈이 한 열만 훑으면 되도록).

```
radsafety.kr 모든 점검항목 정상 (29/29)
2026-07-14 08:30 KST · v0.2.1 · 전체 점검

1. 보안 접속·주소 연결
1-1. 사이트 접속 응답 [o]
1-2. 암호화 접속(https) 강제 [o]

2. 보안 인증서 (만료 2026-09-08)
2-3. 보안 인증서 유효 (55일 남음) [o]
…
8. 실제 브라우저 화면
8-29. 실제 브라우저로 연 홈·로그인 화면 [o]
```

- **머리줄** = 세부항목 총합 축. 전부 정상일 때만 `모든 점검항목 정상 (N/N)`.
  하나라도 어긋나면 `점검항목 문제 N건 · 경고 M건 (정상수/총수 정상)`.
  **경고만 있어도 "모든 … 정상" 이라고 말하지 않는다.**
- **번호** — 큰분류 `1.` `2.` …, 세부항목 `1-1.` `1-2.` `2-3.` … 으로 **큰분류가 바뀌어도 세부번호는 이어서 증가**한다.
  따라서 _마지막 항목 번호 = 총 항목 수 = 머리줄의 분모_. 세 값이 어긋나면 그 자체가 버그 신호다.
- **표식** — `[o]` 정상 · `[!]` 경고 · `[x]` 문제. 이모지·이모티콘은 쓰지 않는다.
- **한 줄 원칙** — 세부항목은 한 줄. 정상 항목은 이름만(수치 detail 은 소음), 경고·실패만 사유를 이어 붙인다.
  큰분류 줄의 괄호 부가정보는 **항목 라벨에 없는 값만**(만료일 등) — 잔여일·응답시간은 이미 라벨에 있으므로 되풀이하지 않는다.
- **되짚기 줄** — 문제·경고가 있으면 마지막에 `문제 7-19, 8-23 · 경고 2-4` 한 줄. 긴 목록에서 표식을 눈으로 찾지 않게.

## `formatReport(summary, opts)` 검증 항목

1. **정상 요약** → 머리줄이 `<호스트> 모든 점검항목 정상 (N/N)`, 둘째 줄에 시각 · 앱 버전 · 점검 모드.
2. **실패 요약** → 머리줄에 문제 건수와 `정상수/총수`, 해당 항목 줄 끝에 `[x]` 와 사유(detail).
3. **경고(warned>0, failed=0)** → 머리줄은 `경고 N건` 형태(=`모든 … 정상` 금지), 항목 줄 끝은 `[!]`.
4. **시각 표기** — `checkedAt`(ISO/UTC)을 **Asia/Seoul** 로 변환해 표기한다(UTC 원문 노출 금지).
5. **되짚기 줄 절단** — 문제·경고 번호는 각각 10개까지만 싣는다(텔레그램 메시지 길이 보호).
6. **요약 누락(`summary === null`)** — 점검 스크립트가 요약을 남기기 전에 죽은 경우로 간주하고, `점검 실행 자체 실패 [x]` 문구를 낸다. **정상으로 오인해선 안 된다.**
7. **실행 로그 링크** — `opts.runUrl` 이 주어지고 **문제가 있을 때** 본문에 포함한다(정상 보고엔 링크가 소음).
8. **번호식 항목 나열(`summary.sections[].items` + `summary.highlights`)** — 영역을 초중급 눈높이 큰분류(접속 / 인증서 / 화면 / 접근차단 / 로그인 경로 / API / 자가진단 / 브라우저)로 묶어 위 형식대로 낸다. `deep`/`shallow` 는 "전체 점검"/"기본 점검"으로 풀어 쓴다(개발자 용어 노출 금지). 그룹 매핑에 없는 새 영역은 원래 이름의 큰분류로 이어 붙인다(조용한 누락 방지).
    - **items 없는 구버전 영역** — 집계 숫자(ok/warn/fail)로 대체 항목을 합성해 총합에서 빠지지 않게 한다.
    - **sections 자체가 없으면** 번호를 매길 대상이 없으므로 머리줄 + `세부 항목 정보 없음(구버전 요약)` 폴백.
9. **표기 방식(`opts.style`)** — `plain`(기본)은 쉬운 말, `both`는 기술 원문 + 쉬운 말 2줄, `tech`는 기술 원문. 알 수 없는 값은 `plain` 으로 떨어진다. 사전에 없는 라벨은 어느 방식에서든 원문.
10. **브라우저 스모크 결합(`opts.smoke`)** — 워크플로의 Playwright 스모크 결과가 별도 스텝(`SMOKE_OUTCOME` env)으로 주입된다.
    - `'success'` → 마지막 큰분류 `실제 브라우저 화면` 의 항목 1개가 `[o]`.
    - `'failure'` → **요약이 정상이어도 이상으로 승격**하고 그 항목이 `[x]`(JS 크래시 백지 화면은 HTTP 점검에 안 보이므로).
    - **항목은 1개** — `SMOKE_OUTCOME` 은 성패만 전달해 홈·로그인 중 어느 쪽이 깨졌는지 알 수 없다. 2개로 쪼개면 실패 시 총 항목 수가 흔들려 `(N/N)` 축이 무너진다.
    - `undefined`(미주입 — 구버전 워크플로·로컬) → 문안에 스모크를 언급하지 않는다(하위 호환).

## `shouldSend(summary, mode, smoke)` 검증 항목

- `off` → 항상 false.
- `fail` → 정상이면 false, 실패·요약누락·**스모크 실패**이면 true.
- `all`·미설정 → 항상 true.
