## 핵심 규칙

1. `id`는 slug 규칙(`documents/resource_slugs.md`와 동일) — 영문 소문자·숫자·하이픈, 한 번 정하면 변경 금지. `profiles.hospital_id`가 이 값을 저장.
2. 병원 개명·합병 시 `id`는 유지하고 `name`만 수정.
3. 폐업·통합 시 항목을 삭제하지 않고 `retired: true`로 표시 — 기존 회원의 `hospital_id` 참조가 끊기지 않도록.
4. `{ id: 'other', name: '기타' }` 항목은 항상 존재 — 회원기관이 아닌 곳(비회원 병원·연구기관 등) 소속자용. "미가입 병원 추정" 집계·기관 추가 요청 대상에서 제외.
5. **출처·범위(2026-09-19 개정, Dr. Ben 결정)**: 학회 기관회원 180개 전수 명단이 아직 없어, 회원 소속란에서 **병원급 기관명만** 추출·정규화한 119개(+`기타`)를 씨앗으로 쓴다(병원급 117 + Dr. Ben 지정 핵의학 전문 의원급 2: 나비편한샘의원·염하용PET센터). 개인 식별정보는 가져오지 않고 기관명만 남겼다(계획서 2-3 원안 "개인 명부는 출처로 쓰지 않는다"의 예외 — 기관명 열만 사용). 제외: 의원급(의원·내과·클리닉·PET센터 등)·요양병원·연구기관·재단·보건소·군부대·대학원·해외 기관·재직 상태값. 표기는 통용명으로 정규화(`화순전남대학교병원`, `삼성창원병원`(구 마산삼성병원), `경희대학교병원`(경희의료원)). 학회 공개 기관회원 명단을 확보하면 그 기준으로 보정 — id 는 유지하고 name 만 고친다.
6. `name`도 중복이 없어야 한다(같은 기관이 표기만 달라 두 번 들어가는 것을 막는다).
7. **이 파일이 전부가 아니다(2026-09-19 개정 2)** — 관리자가 화면에서 등록한 기관은 DB 테이블 `hospitals_custom`에 있고(id `c-…`), 서버는 `src/lib/hospitals.ts`, 클라이언트는 `supabase-browser` select로 둘을 합쳐 본다. 커스텀 기관을 이 파일로 승격할 때는 **id를 그대로**(`c-…`) 옮기고 DB 행은 `retired`가 아니라 삭제해도 된다(같은 id가 양쪽에 있으면 정적이 우선).
