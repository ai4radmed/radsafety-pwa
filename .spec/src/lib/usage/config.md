# src/lib/usage/config.ts — 사용성 집계의 조정 가능한 수치

## 왜 환경변수인가

이 저장소는 모든 변경이 브랜치·PR·검사 두 라운드·릴리스 병합을 거친다. 두 값 다 "실제 수치를 보고 나서 조정하고 싶어지는" 종류라 코드에 박으면 조정 비용이 과하다. 환경변수면 Vercel 에서 숫자만 고치고 재배포한다(Dr. Ben 2026-09-20).

⚠️ 환경변수 변경은 **재배포해야 반영**된다.

## 값

| 이름                      | 기본 | 뜻                                                    |
| ------------------------- | ---- | ----------------------------------------------------- |
| `USAGE_RETENTION_DAYS`    | 35   | 원시 이벤트 보존 일수. 지난 행은 야간 작업이 삭제     |
| `USAGE_MIN_DISPLAY_COUNT` | 0    | 관리자 화면에서 이 값 미만을 가림. 0 이면 가리지 않음 |

숫자가 아니거나 음수면 기본값으로 되돌아간다. 잘못 입력한 환경변수가 집계를 조용히 망가뜨리지 않게 하려는 것이다.

`import.meta.env` 를 먼저 보고 `process.env` 로 폴백한다 — Vercel 런타임 env 는 인라인되지 않을 수 있다(2026-09-20 텔레그램 실측).

## 기본을 0 으로 둔 이유

가리기의 목적은 작은 수치가 다른 정보와 맞춰볼 때 개인을 좁히는 것을 막는 데 있다. 그런데 **앱이 자리를 잡기 전에는 대부분의 수치가 작아서, 가리면 화면이 통째로 비어 버린다**(Dr. Ben 2026-09-20). 보려고 만든 화면이 아무것도 안 보이면 의미가 없다.

이 화면은 관리자 전용이고 관리자는 둘뿐이라 지금은 위험이 낮다. 나중에 화면을 관리자 밖에 보여줄 일이 생기면 5 정도로 올린다.

## displayCount

가리기가 켜져 있고 수치가 기준 미만이면 `<N` 을 돌려준다. 0 은 가리지 않는다 — "없음"은 숨길 것이 없다.
