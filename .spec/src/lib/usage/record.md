# src/lib/usage/record.ts — 익명화와 기록

## 계약

`recordUsage` 는 **절대 던지지 않는다.** 집계 실패가 가입·제출 같은 업무를 되돌리면 안 된다. 실패는 경고 로그 한 줄로 끝내고 `false` 를 돌려준다.

건너뛰는 경우: 허용목록 밖 이벤트, 제외 경로, 서비스 롤 클라이언트 없음, 삽입 오류.

## 비밀키

`USAGE_HMAC_SECRET`. `import.meta.env` 를 먼저 보고 `process.env` 로 폴백한다 — Vercel 런타임 env 는 인라인되지 않을 수 있다(2026-09-20 텔레그램 실측).

**없어도 앱은 정상이다.** 세 키가 NULL 이 되어 사용자 구분 없이 횟수만 센다. Production 에만 넣는 이유가 여기 있다 — 미리보기 배포가 같은 데이터베이스에 실제 활성자 수를 섞지 않게 하려는 것이고, 미리보기는 자연스럽게 횟수만 남는다.

`usageSecretConfigured()` 는 **값을 절대 돌려주지 않고 설정 여부만** 알린다. 상태 점검(`checkConfig` 의 `usage-hmac`)이 이것을 쓴다. 자격증명 지도에 이 키를 적을 때 실물 확인 수단이 된다.

## 키 도출

| 키          | 입력                        | 이어지는 범위 |
| ----------- | --------------------------- | ------------- |
| `actor_key` | `d:<회원식별자>:<KST 날짜>` | 그날 하루     |
| `week_key`  | `w:<회원식별자>:<ISO 주차>` | 그 주         |
| `month_key` | `m:<회원식별자>:<년월>`     | 그 달         |

HMAC-SHA256 의 앞 32자(16진수). 접두 `d:`·`w:`·`m:` 는 서로 다른 기간의 키가 우연히 같아지지 않게 한다.

**날이 바뀌면 `actor_key` 를 다시 계산할 수 없다.** 일간 활성자 수는 정확하되 개인의 시계열은 만들 수 없다. 주·월 키가 있으므로 주간·월간 활성자까지는 세지만 그 이상은 잇지 않는다. 리텐션·코호트는 의도된 포기다.

비밀키를 교체하면 모든 키가 바뀐다 — **교체가 곧 연결 끊기**다. 그래서 월 경계 연 1회 교체를 권한다. 교체 손실은 그 주의 주간 활성자와 그 달의 월간 활성자 한 번뿐이고 일간 수치는 영향이 없다.

## 기간 키는 한국 시간 기준

이용자가 한국에 있다. UTC 로는 전날이어도 한국 시간 기준 날짜를 쓴다 — 그러지 않으면 저녁 9시 이후의 활동이 다음 날로 넘어가 일간 수치가 밀린다.

ISO 주차는 목요일이 속한 해를 따른다(ISO 8601).

## 시각 뭉개기

발생 시각은 시 단위로 자른다. 분·초가 남으면 서비스 로그의 요청 시각과 대조해 개인을 추정하기 쉬워진다. 처리방침 8절이 인정한 한계를 이 집계가 넓히지 않게 하려는 것이다.

## 왜 서버에서 기록하는가

결정적 이벤트 대부분이 이미 서버 액션을 지나가고, 페이지 조회도 서버 렌더라 미들웨어 한 곳이면 모든 화면 이동이 잡힌다. 광고 차단기에 지워지지 않고 클라이언트 번들도 늘지 않는다.

서버가 볼 수 없는 것만 U-3 에서 클라이언트가 맡는다 — 오프라인 접속, 앱 설치, 푸시 허용, 클라이언트 오류.
