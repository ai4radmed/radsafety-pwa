# src/lib/usage/track.ts — 클라이언트 수집 (U-3)

## 무엇만 여기서 잡나

서버가 볼 수 없는 것만이다.

| 이벤트              | 왜 서버가 못 보나                                            |
| ------------------- | ------------------------------------------------------------ |
| `offline_visit`     | 서비스 워커가 캐시로 내준 화면이라 요청이 서버에 닿지 않는다 |
| `pwa_installed`     | 브라우저 `appinstalled` 이벤트                               |
| `push_granted`      | 브라우저 권한 대화상자의 결과                                |
| `login`(password)   | 인증이 브라우저의 Supabase 클라이언트에서 끝난다             |
| `resource_download` | 저장소 공개 주소로 직접 간다                                 |

페이지 조회·가입·아이디 설정·제출·의견은 **서버가 이미 잡는다.** 여기서 또 잡으면 이중 집계다.

`login`(kakao)는 예외적으로 **서버**가 잡는다 — `src/pages/auth/callback.ts` 의 `exchangeCodeForSession` 성공이 곧 로그인 성공이라 클라이언트보다 정확하다.

## 신원은 클라이언트가 주장하지 않는다

이 모듈은 회원 식별자를 **보내지 않는다.** `/api/track` 이 세션 쿠키에서 직접 읽는다. 클라이언트가 "나는 누구다"라고 말하면 그대로 믿는 구멍이 되기 때문이다. 시험이 소스에 `userId`·`actor_key` 가 없음을 고정한다.

## 오프라인 큐

오프라인 사용 자체가 이 앱의 핵심 지표라, 오프라인에서 생긴 사건은 버려지면 안 된다. `localStorage` 한 벌에 쌓아 두었다가 온라인이 되면 보낸다.

- 큐 상한 50건. 오래 오프라인이어도 무한히 자라지 않는다
- 한 번에 20건씩 전송. 서버도 같은 값으로 자른다
- 전송 실패면 큐를 유지하고 다음 기회를 기다린다
- `localStorage` 가 막힌 브라우저에서도 **던지지 않는다** — 집계를 포기할 뿐 앱은 돈다

겹쳐 부른 `flushTracking` 은 즉시 반환한다. 같은 묶음을 두 번 보내지 않으려는 것이다.

## 발생 시각

큐에 넣을 때의 시각을 함께 저장한다. 오프라인에서 쌓인 것이 사흘 뒤에 전송돼도 **그때 시각으로** 남아야 집계가 맞는다.

다만 서버는 이 시각을 믿지 않는다 — 미래이거나 7일보다 과거면 수신 시각으로 친다(`safeAt`). 조작된 시각이 지나간 집계를 흔들지 못하게 한다.

## 초기화

`BaseHead.astro` 에서 1회. 공개·회원 화면 양쪽이 이 컴포넌트를 쓰므로 한 곳이면 된다. 화면 전환(View Transitions)마다 다시 불려도 중복 등록되지 않는다.
