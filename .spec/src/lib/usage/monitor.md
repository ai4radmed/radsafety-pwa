# src/lib/usage/monitor.ts — 사람이 아닌 요청 판정

## 왜 생겼나 (2026-09-21)

회원 공지 전인데 홈 화면 비로그인 조회가 하룻밤에 22건 찍혔다. 매일 도는 상태 점검(`check-production.mjs` 의 공개 화면·응답 시간 검사, Playwright 스모크)과 배포 후 점검이 홈을 반복해서 연 것이다. 서버 렌더 화면은 기계 요청도 사람과 똑같이 조회로 기록된다.

그대로 두면 "많이 열린 화면" 순위가 기계가 좋아하는 화면으로 채워지고, 다음에 무엇을 만들지 정하는 근거가 오염된다.

## 두 겹 판정

| 겹  | 방법                       | 잡는 것                                        |
| --- | -------------------------- | ---------------------------------------------- |
| 1   | `x-radsafety-monitor` 헤더 | **우리 무인 점검** — 스스로 밝힌다             |
| 2   | 식별 문자열의 표식         | 크롤러·헤드리스 브라우저·명령줄 도구·배포 점검 |

1겹이 핵심이다. 브라우저 식별 문자열을 진짜처럼 흉내 내는 도구(Playwright 의 Desktop Chrome 장치 설정)도 헤더 하나로 빠진다. 2겹은 우리가 통제하지 못하는 기계를 위한 안전망이고 완벽하지 않다.

식별 문자열이 아예 없는 요청도 기계로 본다 — 브라우저는 항상 보낸다.

## 헤더를 붙이는 곳

- `scripts/check-production.mjs` 의 `fetchFollow` — 값 `check-production`
- `playwright.config.ts` 최상위 `use.extraHTTPHeaders` — 값 `playwright`. 프로덕션 스모크·월간 점검·로컬 E2E 전부. 월간 점검은 사람이 조작하지만 **시스템 계정**(`monthly-check`)이라 실제 사용이 아니다

새 무인 점검을 만들면 이 헤더를 붙인다. 안 붙여도 2겹이 대개 잡지만, 붙이는 것이 규약이다.

## 적용 지점

`src/middleware.ts`(화면 조회·벽)와 `src/pages/api/track.ts`(클라이언트 수집) 둘 다. 헤드리스 스모크가 화면을 열면 클라이언트 수집도 같이 켜지므로 한쪽만 거르면 샌다.

## 틀려도 안전하다

판정이 틀리면 결과는 "기록 안 함"뿐이다. 앱 동작에는 영향이 없다. 사람을 기계로 오판하면 그 사람의 조회가 빠질 뿐이고, 기계를 사람으로 오판하면 종전과 같다.
