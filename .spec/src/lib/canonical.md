# 명세: src/lib/canonical.ts

## 역할 요약

페이지의 **표준(canonical) URL** 계산. 2026-11-12 신설 — 같은 페이지가 `/guide` 와 `/guide/` 두 주소로 모두 200 으로 열리는데 표준 태그가 요청 경로를 그대로 따라가, 두 주소가 서로 다른 표준을 주장했다(Google Search Console "중복 페이지, Google에서 사용자와 다른 표준을 선택함", 2026-09-25 관측).

## Public API

| 이름                           | 설명                                                              |
| ------------------------------ | ----------------------------------------------------------------- |
| `canonicalUrl(pathname, site)` | 경로를 슬래시로 끝나게 정규화한 뒤 `site` 기준 절대 `URL` 로 반환 |

## 핵심 규칙

1. **sitemap 과 같은 형태로 통일** — sitemap 은 슬래시로 끝나는 주소(`/guide/`)만 싣는다. 표준 태그도 항상 그 형태를 낸다.
2. **파일 경로는 그대로** — 마지막 세그먼트에 `.` 이 있으면(`/rss.xml`) 슬래시를 붙이지 않는다.
3. **리다이렉트하지 않는다** — 주소는 둘 다 계속 열린다. 내부 링크가 슬래시 없는 형태라 308 을 걸면 모든 이동에 왕복이 하나 늘고, Astro 내부 경로·헬스체크(`/notifications` → 302)에 영향이 간다. 표준 신호만 통일해도 경고가 남으면 그때 리다이렉트를 검토한다(보관 브랜치 `wip/trailing-slash-308-redirect`).
4. 쿼리스트링·해시는 표준에 싣지 않는다(`pathname` 만 받는다).
