# src/lib/public-paths.ts — 2계층 공개 경로 단일 권위

## 왜 별도 모듈인가

이 목록은 원래 `auth-handler.ts` 안의 지역 배열이었다. U-2 에서 **서버 미들웨어도 같은 판정이 필요**해졌다 — 비로그인이 회원 전용 화면을 열면 사용성 집계가 그것을 조회가 아니라 `gate_blocked` 로 세야 하기 때문이다.

목록을 두 벌로 두면 반드시 어긋난다. 한쪽만 고친 날 리다이렉트는 되는데 집계는 벽으로 세거나 그 반대가 된다. 그래서 모듈 하나로 빼고 양쪽이 import 한다.

## 계약

| export               | 뜻                                            |
| -------------------- | --------------------------------------------- |
| `PUBLIC_PATHS`       | 비회원이 열 수 있는 경로 접두 목록            |
| `isPublicPath(path)` | 접두 일치 판정. `/` 는 **정확히 일치할 때만** |

`/` 를 접두로 쓰면 모든 경로가 공개가 된다. 이 예외가 규칙의 핵심이라 시험으로 고정한다.

## 소비자

- `src/lib/auth-handler.ts` — 비로그인이 회원 전용 경로에 오면 `/login?from=` 으로 리다이렉트
- `src/middleware.ts` — 같은 조건에서 `gate_blocked` 기록(U-2)

## 목록 변경 시

메뉴를 공개/회원 사이로 옮기면 **리다이렉트와 집계가 함께 바뀐다.** 이것이 의도다. 다만 집계 해석에는 단절이 생기므로, 옮긴 날짜를 기억해 두고 `gate_blocked` 추세를 볼 때 그 앞뒤를 나눠 본다.

## 익명 제안 조회가 공개인 이유

`/proposal-lookup` 은 접수증 코드를 가진 사람이 본인이다. 로그인을 요구하면 조회와 계정이 다시 묶여 3단계에서 끊은 연결이 되살아난다. 반대로 `/proposals`(작성)와 `/my-proposals` 는 회원 전용이다.
