# src/pages/api/cron/usage-rollup.ts — 롤업 크론

## 계약

`GET /api/cron/usage-rollup`. Vercel Cron 이 `Authorization: Bearer <CRON_SECRET>` 로 하루 1회 호출한다. 관리자는 브라우저로 수동 실행할 수 있다(admin 쿠키). `?dry=1` 이면 계산만 하고 쓰지 않는다.

## 왜 감시 크론과 경로를 나누나

`CRON_SECRET` 은 같이 쓰되 경로는 따로 둔다. 한쪽이 실패해도 다른 쪽은 돌아야 하고, 실패 원인이 섞이면 어느 쪽이 깨졌는지 알 수 없다.

Vercel Hobby 는 크론 개수가 아니라 **빈도**가 제약이다(하루 1회). 두 개를 두는 데는 문제가 없다.

## 실행 시각

한국 시간 새벽 3시 40분(UTC 18:40). **자정을 넘긴 뒤**여야 전날 하루치가 완결된 상태로 집계된다. 감시 크론(한국 시간 7시)과도 떨어뜨려 두 작업이 겹치지 않게 한다.

Vercel 은 예정 시각에서 최대 한 시간 늦게 실행할 수 있다. 그래서 새벽 이른 시각으로 잡되, 흔들려도 같은 날 안에 머물도록 여유를 둔다.

## 실패해도 200

크론 실패를 상태 코드로 알리면 Vercel 이 재시도하며 같은 실패를 반복한다. 응답 본문의 `ok: false` 와 `error` 로 보고하는 편이 낫다 — 실행 기록에 남고, 수동으로 열어 보면 이유가 바로 보인다.
